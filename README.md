## Agent 核心概念与技术速查

> 框架只是工具，理解背后的概念才能做出正确选型。

### 🧠 Agent 设计模式

| 模式 | 含义 | 代表框架 | 适用场景 |
|------|------|---------|---------|
| **ReAct** | Reasoning + Acting：LLM 交替"思考"和"行动" | LangChain, pydantic-ai | 单 Agent 工具调用 |
| **Plan-and-Execute** | 先规划全部步骤，再逐步执行 | Semantic Kernel Planner | 复杂任务分解 |
| **Reflexion** | 执行后自我反思，修正错误 | 手动实现（LangGraph 循环） | 代码生成、数学推理 |
| **Tool Use Loop** | LLM 决定调用工具 → 执行 → 结果喂回 → 循环 | 所有框架的基础 | 通用 |
| **Multi-Agent Debate** | 多个 Agent 对同一问题辩论达成共识 | AutoGen GroupChat | 提高准确性 |
| **Supervisor** | 主管 Agent 分配任务给子 Agent | CrewAI hierarchical, LangGraph | 任务分配 |
| **Handoff** | Agent 完成自己的部分后移交给下一个 | OpenAI Agents SDK | 客服分流 |

### 🔧 Agent 基础设施层

| 技术 | 含义 | 在框架中的体现 | 为什么重要 |
|------|------|--------------|----------|
| **Function Calling** | LLM 输出结构化的函数调用请求（非纯文本） | OpenAI tool_calls, Anthropic tool_use | Agent 能力的基石 — 没有它就只能输出文本 |
| **Structured Output** | LLM 输出符合指定 JSON Schema 的结构化数据 | pydantic-ai output_type, Vercel AI SDK Zod | 可靠地将 LLM 输出接入后端系统 |
| **RAG** | Retrieval-Augmented Generation：检索 → 注入上下文 → 生成 | LangChain Retriever, Spring AI QuestionAnswerAdvisor | 让 LLM 使用私有数据 |
| **Embedding** | 文本 → 向量表示，用于语义搜索 | LangChain Embeddings, FAISS/Chroma | RAG 的前置步骤 |
| **Vector Store** | 存储和检索文本向量的数据库 | FAISS, Chroma, Pinecone, Weaviate, pgvector | RAG 的存储层 |
| **Guardrail** | 输入/输出安全护栏（防注入、内容过滤） | OpenAI Agents SDK Guardrail, NeMo Guardrails | 生产必备 — 防止 Agent 做危险操作 |
| **Observability** | Agent 执行追踪、Token 统计、延迟监控 | LangSmith, Phoenix, Langfuse, OpenTelemetry | 调试和优化 Agent 行为 |
| **Evaluation** | Agent 质量评测（准确率/幻觉率/工具调用成功率） | Ragas, DeepEval, LangSmith Eval | 衡量 Agent 是否达标 |

### 🔌 Agent 通信协议

| 协议 | 含义 | 现状 | 适用场景 |
|------|------|------|---------|
| **MCP** (Model Context Protocol) | Anthropic 提出的 Agent ↔ 工具标准协议 | 生态快速扩展中 | 统一工具接入（一个工具服务，所有 Agent 都能调用） |
| **A2A** (Agent-to-Agent) | Google 提出的 Agent 间通信协议 | 早期阶段 | 跨组织/跨框架的 Agent 协作（Agent Card 服务发现） |
| **ACP** (Agent Communication Protocol) | IBM/BeeAI 提出的 Agent 间通信协议 | 早期阶段 | 内部 Agent 编排（更轻量，3 个 API，SSE 原生） |
| **OpenAI Plugin** | OpenAI 定义的插件标准（OpenAPI + Auth） | 被 GPT Actions 替代 | ChatGPT 插件（已弱化） |
| **Tool Use** (Anthropic) | Claude 的原生工具调用格式 | 成熟 | Claude Agent |
| **OpenAPI/Swagger** | REST API 描述标准，可自动转成 Agent 工具 | 成熟 | 让 Agent 调用已有 REST API |

### 🧱 Agent 记忆体系

| 记忆类型 | 含义 | 实现方式 | 框架支持 |
|---------|------|---------|---------|
| **短期记忆** | 当前对话的消息历史 | 消息列表（message_history） | 所有框架 |
| **长期记忆** | 跨会话的用户偏好/知识 | 向量数据库 + 总结 | LangChain Memory, Mem0 |
| **工作记忆** | 当前任务的中间状态 | 状态字典 / checkpoint | LangGraph State, AutoGen context |
| **情景记忆** | 过去类似任务的经验 | 向量检索历史案例 | 手动实现 |
| **Compaction** | 对话过长时压缩历史消息 | 摘要 + 滑动窗口 | Code Puppy, LangChain |

### 🛡️ Agent 安全

| 威胁 | 含义 | 防御措施 |
|------|------|---------|
| **Prompt Injection** | 用户输入恶意指令覆盖系统 prompt | 输入清洗、角色分离、Guardrail |
| **Tool Abuse** | Agent 被诱导执行危险工具（删库/发邮件） | 工具白名单、权限分级、human-in-the-loop |
| **Data Leakage** | Agent 通过工具或回复泄露敏感数据 | 输出过滤、PII 脱敏、数据分级 |
| **Infinite Loop** | Agent 陷入无限工具调用循环 | max_turns/max_steps 限制、超时 |
| **Cost Explosion** | Agent 大量调用 LLM 导致费用失控 | Token 预算、调用次数限制 |
